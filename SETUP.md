# SETUP.md — как закрыть 4 блокирующих пункта

Пошагово, можно проходить по порядку. Везде, где нужно вставить значение
в `.env` — сначала скопируйте `.env.example` в `.env` (в корне репо),
если ещё не сделали:

```bash
cp .env.example .env
```

`.env` уже в `.gitignore` — никогда не попадёт в git, можно спокойно
вписывать туда реальные значения.

---

## 1. DATABASE_URL

Два варианта: быстрый локальный (чтобы сегодня же всё проверить) и
настоящий облачный (для реального деплоя). Начните с локального — он
не требует регистрации нигде.

### Вариант A — локально прямо сейчас, без регистрации

Prisma умеет поднять Postgres прямо в терминале:

```bash
npx prisma dev
```

Команда напечатает готовую строку подключения вида
`postgresql://...@localhost:51213/...` — скопируйте её в `.env` как
`DATABASE_URL`. Терминал с этой командой должен оставаться открытым,
пока вы работаете с БД (это и есть сама база).

После этого в **новом** терминале:

```bash
npx prisma migrate dev --name init
npx prisma db seed
```

Первая команда создаст таблицы, вторая — загрузит реальный контент
курса «Асортимент». Дальше `npm run dev` — и весь функционал (вход,
хаб, курс, админка) заработает на реальных данных.

### Вариант B — облачный Postgres (для деплоя на Vercel)

Рекомендую **Neon** (bezplatный тариф, Vercel сам предлагает его как
дефолтный Postgres-провайдер):

1. Зайдите на [neon.tech](https://neon.tech) → Sign Up (можно через
   GitHub/Google).
2. Create a project → выберите регион поближе к пользователям
   (например, Frankfurt / EU Central).
3. На странице проекта будет готовая строка подключения
   (`postgresql://user:password@ep-....neon.tech/dbname?sslmode=require`)
   — скопируйте её.
4. Вставьте как `DATABASE_URL` в `.env` (для локальной работы) — и
   позже в Vercel → Project Settings → Environment Variables (для
   деплоя).
5. Прогоните те же две команды, что и в варианте A
   (`prisma migrate dev --name init`, `prisma db seed`), но уже против
   этой базы.

Альтернативы Neon (если уже пользуетесь чем-то из этого) — Vercel
Postgres (Vercel → Storage → Create Database), Supabase, любой другой
managed Postgres. Всем подходит одна и та же строка `postgresql://...`.

**Проверить, что БД подключена и видно данные:**

```bash
npx prisma studio
```

Откроет визуальный браузер таблиц в браузере — если видите таблицы
`Course`, `Module`, `Lesson` и в `Course` есть строка «Асортимент
Carlsberg Ukraine» — всё сработало.

## 2. Файл с сотрудниками

Это не про действие в терминале — просто пришлите файл мне (в чат,
как вложение, или путь к нему на диске, если он уже здесь на
компьютере). Формат неважен (CSV/Excel/Google Sheets export/просто
текст) — я разберу структуру, как только увижу.

Чтобы не пришлось переписывать импорт-скрипт дважды, идеально, если в
файле (или вы сможете быстро добавить) есть:

- **email** сотрудника;
- **код должности** (RM/ASM/SV/SR/MR);
- **кто руководитель** (email или ID руководителя — не просто название
  отдела, а именно ссылка на конкретного человека);
- **код для входа** (тот, что сотрудник вводит на экране регистрации —
  из приложения Monolit Agent, вида `ml03005`). Если этого поля в
  файле нет — тоже нормально, скажете, и решим, что делать (импортировать
  без него и добавить позже, или собрать отдельно).

Территории (регионы), если они у вас вообще выделены отдельно от
должности — тоже полезно, но не обязательно для первого прохода.

## 3. Аккаунт Resend (для писем с PIN)

1. Зайдите на [resend.com](https://resend.com) → Sign Up (email,
   GitHub или Google).
2. Подтвердите почту по ссылке из письма.
3. В дашборде: **API Keys** (в левом меню) → **Create API Key**.
   - Name: например `carlsberg-lms` (просто для себя, чтобы отличать
     ключи, если их будет несколько).
   - Permission: `Full access` подойдёт для старта.
4. Скопируйте ключ **сразу** (он показывается один раз, начинается на
   `re_`) → вставьте в `.env` как `RESEND_API_KEY`.

На этом достаточно, чтобы письма уже отправлялись — просто с адреса
`onboarding@resend.dev` (тестовый домен Resend, работает сразу, без
дополнительной настройки).

### Опционально — свой домен для отправки

Если хотите, чтобы письма шли не с `resend.dev`, а с адреса на вашем
домене (например `noreply@carlsberg-adapt.com`):

1. В Resend: **Domains** → **Add Domain** → введите домен.
2. Resend покажет несколько DNS-записей (DKIM, SPF, иногда DMARC) —
   их нужно добавить в настройках DNS вашего домена (там же, где
   покупали домен/настраивали остальные записи).
3. Подождите верификации (обычно от нескольких минут до пары часов,
   зависит от DNS-провайдера) — в Resend статус домена станет
   "Verified".
4. Добавьте в `.env`: `RESEND_FROM_EMAIL=noreply@ваш-домен.com`.

Без этого шага всё тоже работает — письма просто будут от resend.dev.

## 4. SESSION_SECRET и CRON_SECRET

Это просто две длинные случайные строки, никакой регистрации не
нужно — сгенерировать самому. **Два РАЗНЫХ значения**, не используйте
одно и то же для обеих переменных.

**Если есть Git Bash / macOS / Linux:**

```bash
openssl rand -hex 32
```

Запустите дважды (второй раз — для второй переменной), скопируйте
каждый результат в `.env`.

**Если удобнее через Node (у вас он уже установлен для проекта):**

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

То же самое — запустить дважды.

Результат выглядит как случайная строка из 64 символов
(`a3f9e1...`) — вставьте один результат как `SESSION_SECRET`, другой
как `CRON_SECRET` в `.env`.

## Когда все 4 пункта закрыты

`.env` должен содержать все пять значений (`DATABASE_URL`,
`SESSION_SECRET`, `RESEND_API_KEY`, `CRON_SECRET` — и опционально
`RESEND_FROM_EMAIL`). Дальше:

```bash
npm install
npx prisma migrate dev --name init
npx prisma db seed
npm run dev
```

Откройте `http://localhost:3000` — должно перекинуть на `/register`.
Дальше уже нужны реальные сотрудники в БД (пункт 2), чтобы залогиниться
и увидеть хаб/курс с реальными данными — но само приложение уже будет
живое, не падать на "нет подключения к БД".

Когда будете готовы к реальному деплою на Vercel — те же переменные
(с реальными, не локальными значениями для `DATABASE_URL`) заводятся
в Vercel → Project Settings → Environment Variables. Список и что куда
— см. конец `TODO.md`.
