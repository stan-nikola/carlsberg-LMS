## Стенд /admin/design і кольори елементів

- Стенд `/admin/design` (`components/admin/DesignStand.tsx`, `lib/designTokens.ts`)
  — лише для **супер-адміна** (`SUPER_ADMIN_PASSWORD`, рівень "super" у
  admin_session, `lib/adminSession.js getAdminLevel`). Крутить токени
  наживо як прев’ю (localStorage, `DesignTokensOverride`) і «Зберегти для
  всіх» пише їх в `AppSetting(design-tokens)` — кореневий layout вставляє
  `<style>:root{…}</style>` поверх tokens.css (`lib/designSettings.ts`,
  whitelist по DESIGN_TOKENS, кеш 60с; layout через це force-dynamic).
  Рішення користувача 2026-09-16: зміни дизайну без git. Новий регульований
  токен = рядок у `DESIGN_TOKENS` + дефолт у tokens.css. Кольори стенд не
  чіпає (рішення користувача) — **крім одного вторинного кольору бренду
  (2026-10-04)**. Джерело — Carlsberg Group design guide (carlsberggroup.com →
  design guide → Colours), не Malty: основні — Carlsberg green і білий;
  вторинних сім (зелений 23-177-105, золото 180-145-50, жовтий 255-180-0,
  синій 30-100-170, бірюзовий 20-165-185, бордовий 120-40-58, лососевий
  245-165-150), і правило гайду — у макеті лише ОДИН вторинний.
  Користувач обрав окремий колір для кожного великого елемента хабу й
  кабінету керівника: ініціали, кружки відзнак, іконка на картці курсу,
  кільце фото, зірка рівня, сертифікати, банер тесту, іконки налаштувань.
  Палітра — `lib/accentPalette.ts`: сім вторинних × три відтінки (світлий =
  55% з білим, основний, глибокий = 70% з чорним) + Carlsberg green і сірі
  Malty 100/80/60. Кожен елемент — КОЛІР + ВИГЛЯД (заливка / тон / контур /
  градієнт / плоска — лише ті, що мають сенс для елемента), незалежні одне
  від одного. Токени `--accent-<id>` (сам колір), `-bg`, `-fg` (текст/значок
  за контрастом WCAG), `-bd` (рамка) генерує `accentTokenValues`; дефолти
  (`ACCENT_ELEMENTS.pick`, фінальний вибір користувача з конструктора
  CarLS Accents 2026-10-04) дублюються в tokens.css — `accentPalette.test.ts`
  звіряє. CSS елемента бере лише ці чотири токени, не міксує колір сам.
  **Відзнаки й зірка рівня — янтарні (2026-10-05, скарга з iPhone: бліді
  зелений/бірюзовий тон зливались зі світлим фоном карток):** обидва —
  «Жовтий» гайду `#ffb400` (справжнього помаранчевого в палітрі Carlsberg
  Group нема, жовтий найближчий): відзнаки — градієнт, зірка — заливка;
  під значком відзнаки `text-shadow`, щоб жовта емодзі (⭐) не зливалась.
  **Кільце фото** на зеленій картці профілю — золото світле `#d6c38e`
  (2026-10-05): Carlsberg green, що стояв раніше, зливався з темно-зеленою
  карткою — рамки не було видно. Хаб і кабінет — одна картка (`.profile-card
  .avatar`, `--accent-ring`).
  На /admin/design — «Кольори елементів»: готові гами (лише кольори, вигляд
  лишається), «Усі однаково», список елементів і для обраного «1 · Вигляд» /
  «2 · Колір», де кожна плитка — сам елемент у цьому кольорі.
  Підказки (НЕ заборони, рішення користувача) — `lib/accentAdvice.ts` (з
  тестом): не більше двох вторинних на екрані (`ACCENT_SCREENS`; відтінки
  одного кольору, Carlsberg green і сірі не рахуються), кольори, схожі на
  статуси (зелений/жовтий/бордовий/лососевий), біля статусів, і видима
  поверхня елемента на темно-зеленій картці з контрастом < 3:1. Новий
  великий елемент = рядок в `ACCENT_ELEMENTS` + екрани в `ACCENT_SCREENS`
  (+ `NEAR_STATUS`, якщо поруч статуси) + CSS на `--accent-<id>-*` +
  дефолт у tokens.css + мініатюра в `AccentSample` і місце на макеті
  (`SCREENS` + розмітка мок-екрана) у `components/admin/ColorMap.tsx`.
  **Карта екранів (2026-10-05):** на /admin/design «Кольори елементів» —
  `ColorMap`: п’ять макетів (Команда, Курси, Досягнення, Плеєр,
  Сповіщення) на тих самих `--accent-*` токенах; клік по елементу → панель
  «що це / на екранах / порада», вигляд, колір, ⚠ лише за те, що додає саме
  ця плитка. Налаштовано 30 елементів у 5 групах (`ACCENT_GROUPS`): великі,
  прогрес, навігація і кнопки, мітки і цифри, статуси. У нових елементів
  дефолт — «Як зараз (Malty)» (`now` у `ACCENT_ELEMENTS`, `NOW_ID`) або
  колір палітри, що збігається з колишнім: нічого не змінилось, доки не
  оберуть. Статус — один колір на всі місця (пілюля, сегмент «Стан
  команди», клітинка матриці, точка плану); «Не почали», «Неактивні»,
  «Не складено» в матриці лишились у «Сприйнятті». Адмінка статусів не
  міняє (`.adm-shell` в admin.css повертає «Як зараз»).
  **Сприйняття кольорів (2026-10-04):** `PERCEPTION_FIXES` у
  `lib/designTokens.ts` — рекомендації «як зараз / рекомендовано» (WCAG:
  текст 4.5:1, рамки полів 3:1; дальтонізм — значки ✓ ! ⏱ на пілюлях;
  зміст статусів — «Не складено» світло-бурштиновий, «Не почали» сірий,
  «Неактивні» штрихування). Правило — не новий колір, а темніший відтінок
  ТОГО Ж кольору Malty (`color-mix(… var(--cb-*) N%, var(--cb-black))`).
  Токени `--p-*` у tokens.css, дефолт = як було; адмінка скидає їх
  (`.adm-shell` в admin.css). Новий колір тексту на кольоровому фоні в хабі
  чи кабінеті — через `--p-*`, а не сирий `--cb-fail`/`--cb-notification`.
  Кольори Malty `information` (hold, live, new…) — це мітки статусів, не
  акценти бренду: не використовувати для оформлення. Глобальну кольорову
  схему «ролями» (одна роль фарбує все) користувач свідомо відхилив —
  натомість 2026-10-05 сам попросив КОЖЕН елемент окремо (карта екранів
  вище); адмінка кольорів не міняє.
  Заголовок адмінки — «Адміністратор», для рівня super над ним плашка
  «super» (`.adm-level-pill`, AdminShell.jsx).
